01 / Why this project

The problem: model files are large, valuable, and awkward to move

A single-machine file store becomes a bottleneck as model size and access demand grow.

SIZELLM weights can be multiple gigabytes.

Whole-file buffering is memory-expensive.

AVAILABILITYOne node failure should not make a model unavailable.

Copies must be synchronized and discoverable.

OPERATIONSTransfers need to be observable.

A teacher or operator should see what happened.

One logical model repository, distributed physical storage.

04 / Replication & integrity

The Coordinator controls the workflow; the primary moves replica data

Replication is concurrent, peer-to-peer, and checked with SHA-256.

Control path

Coordinator selects a primary and target replica nodes.

Replica records move from SYNCING to SYNCED.

NATS emits REPLICATION_STARTED and REPLICATION_COMPLETED.

Data path

Primary receives the client stream through gRPC.

Primary calls peers directly through ReplicateToNode.

Checksums match across source, replicas, and download.

Integrity contract: Coordinator hash = primary hash = replica hash.

06 / Coordination & fault handling

Distributed state needs explicit rules

Placement reservations, read/write locking, and heartbeat-based detection work together.

LOAD-AWARE PLACEMENT

NodeSelector sorts by model count plus pending reservations.

A mutex makes read-decide-reserve atomic.

Concurrent uploads do not all choose one stale least-loaded node.

PER-MODEL CONSISTENCY

Concurrent downloads share a read lock.

Delete and replication acquire exclusive access.

A download is never routed during a model mutation.

Failure detection: the Coordinator polls nodes every 5 seconds and marks unreachable nodes OFFLINE.

10 / Results & boundaries

What the current project demonstrates

A strong prototype is clearer when its guarantees and gaps are both explicit.

VERIFIED IN INTEGRATION TEST

Three generic nodes start on ports 5001–5003.

A synthetic 2 MB model uploads through the Coordinator.

Files appear on all three node directories.

SHA-256 matches across source, replicas, and download.

Metadata and replica records are inspected.

KNOWN LIMITATIONS / NEXT STEPS

No automatic re-replication after permanent node loss.

Peer addresses are statically configured.

No dynamic discovery, gossip, or DHT layer.

Production hardening: auth, quotas, and durable retries.
